# Genesis Engine · Biome.AI

Ранний **играбельный прототип**, а не законченная игра из концепции. Windows, C#/.NET 8, Raylib-cs 7.0.2. Игрок меняет рельеф, наблюдая автономную популяцию.

## Visual Studio

1. Установите Visual Studio 2022 17.8+ и .NET 8 SDK (workload «Разработка классических приложений .NET»).
2. Откройте `GenesisEngine.sln`.
3. Установите `Genesis.Engine.App` запускаемым проектом, нажмите F5. При первом запуске требуется интернет для NuGet.

```powershell
dotnet build GenesisEngine.sln -c Release
dotnet test GenesisEngine.sln -c Release
dotnet run --project src/Genesis.Engine.App -c Release
```

## Управление

| Действие | Управление |
|---|---|
| Поднять / опустить ландшафт | ЛКМ / ПКМ |
| Размер кисти | Колесо мыши |
| Пауза (кисти продолжают работать) | Пробел |
| Скорость 1× / 2× / 4× | 1 / 2 / 3 |
| Повторно создать мир с тем же seed | R |
| Выход | Esc |

Цвет агентов зависит от агрессии и социальности генома. Размер зависит от гена размера. Оттенки клеток показывают высоту. Симуляция обновляется с фиксированным шагом 1/30 с независимо от частоты отрисовки.

## Архитектура и границы

- `src/Genesis.Engine.Core`: мир и автономная симуляция без графических зависимостей.
- `src/Genesis.Engine.App`: окно Raylib, визуализация, ввод и fixed-step цикл.
- `tests/Genesis.Engine.Core.Tests`: xUnit-проверки ядра.
- `.github/workflows/build.yml`: сборка и стандартный запуск тестов на Windows.

Мозг прототипа — **нейросеть фиксированной топологии с наследованием весов**, не полноценный NEAT. Правила энергии, питания и размножения программные: нейросеть определяет движение, а не всю физику мира. Социальные гены пока не означают существование племён.

Пока **не реализованы**: NEAT с инновациями и видообразованием, ECS Arch/HypEcs, климатические кисти и катаклизмы, хищники, хижины, фермерство, войны, союзы, сохранение мира, музыка и плагины. Производительность 10 000 агентов / 60 FPS не заявляется и требует отдельного профилирования. Это база для дальнейших итераций, не B2B-платформа.

## Проверки

`--smoke` открывает настоящее окно и автоматически закрывает его после 120 кадров:

```powershell
dotnet run --project src/Genesis.Engine.App -c Release -- --smoke
```

Если в ограниченном окружении VSTest падает с `Win32Exception (5)` при отслеживании родительского процесса, можно выполнить непараметризованные `[Fact]` проверки напрямую:

```powershell
dotnet run --project tools/Verify -c Release
```

Это вспомогательный runner для синхронных `[Fact]`, не замена полноценному xUnit/VSTest (не поддерживает fixtures, theories, async).
